# CLAUDE.md

A local practice simulator for the Google Cloud Associate Cloud Engineer exam, plus its theory site. Read
`CONTRIBUTING.md` first: its **no exam content** rule binds you too. Never write a question from a remembered
exam item, a dump or a practice test.

## Commands

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
streamlit run app.py                           # the simulator
bin/start.sh / bin/stop.sh                     # the simulator in Docker, syncing data/history.json both ways
pytest -q                                      # must stay green; runs on a generated fixture bank
ACE_TEST_BANK_DIR=banks/private pytest -q      # the same tests on the real (private) bank
pytest tests/container                         # the container, in a real browser; needs Docker and Playwright
python scripts/kb.py check                     # bank integrity
python scripts/kb.py lint                      # the question standard (docs/question-standard.md)
python scripts/kb.py blueprint --min 3 --strict  # every guide bullet has 3+ questions
python scripts/kb.py add --file newq.json      # add questions through validation
python scripts/kb.py plan 10%                  # where an expansion would put its questions (/expand runs the rest)
python scripts/kb.py rework 50                 # which seen questions a rework would replace (/rework runs the rest)
```

After changing dependencies in `pyproject.toml`, regenerate both lock files with the command at the top of each.

## Releases

`RELEASE.md` is the process and `VERSION` the source of truth, with semantic versioning. Add a line to `CHANGELOG.md` under
`Unreleased` for anything a user would notice. Open work is in the GitHub issues; `docs/plans/` holds machine-readable plans.

## Map

- `src/blueprint.py`: the exam guide as data, and the closed list of subtopics. A question must use one.
- `src/models.py`: schemas, bank persistence and the uniqueness limits. `src/exam_engine.py`: sampling, timer,
  scoring; no Streamlit imports. `src/retrospective.py`: the PDF report, plus `in_review`, `margin_lede` and `timing_facts`, which the in-app report shares.
  `src/study_links.py`: theory sections, site URLs and video chapters, from `data/study_links.json` (generated by
  `scripts/build_study_links.py`; never edit it). `src/history_sync.py`: the merge behind `bin/`. `app.py`: the Streamlit shell, with the in-app score report, Material 3 tokens in `BASE_CSS` (fixed bar heights `--ace-hdr`/`--ace-nav`) and `SPLITTER_JS`, which runs in the parent page to resize the study panel. `src/paths.py`: the only place that
  says where history and reports go; `ACE_STATE_DIR` moves them.
- `src/expansion.py`: the expansion plan (`kb.py plan`, `slots`), the gates on a candidate (`vet`, `blind`,
  `accept`) and the doc-page reader (`doc`). `.claude/skills/expand/` is the `/expand` skill that drives them and
  `.claude/agents/ace-blind-solver.md` the agent that answers candidates without the key. Run state is in the
  gitignored `build/expand/`. `.claude/skills/rework/` is the `/rework` skill: the same gates, but each slot
  replaces a question the user has already seen (`rework_plan`, the `rework-*` findings, and the retirement in
  `accept`). `kb.py rework` is the only code that reads the attempt history for it, and it takes ids only. Run state
  is in `build/rework/`.
- `banks/private/`: **the bank, source of truth, and not in git** (`banks/README.md`). It holds `sections/*.json`,
  a generated `register.json` (run `kb.py reindex`, never edit it), `retired.json` and the run ledgers in `reviews/`.
  `ACE_BANK_DIR` points everything at another bank. `src/paths.py` `bank_dir()` is the only place that decides.
- `theory/*.md`: **the theory, source of truth**, published by GitHub Pages (just-the-docs; config in
  `_config.yml`).
- `theory/pdf/`: optional local PDF build. `assemble.py` generates its input from the pages; do not edit the output.
- `theory/video/`: sources of the narrated course. The build needs a private slide kit that is not in this repo.

## Rules

- Write questions to version 2 of `docs/question-standard.md`: a scenario (usually across two or more areas of the
  guide; associate-level migrations count), one decision, four options of which at least two are close siblings of
  the key (or four or five for a "Choose two" question), a rationale for each, exact and real role IDs and commands
  in backticks, `decided_by`, `step` and `trap`, and a `doc_ref` you have actually checked. Most questions set
  `also_tests`. A candidate's report of the exam's format is fine to follow; a remembered item never is. Never reuse an id; removed ids are in the bank's `retired.json`.
- To add many questions, run the `/expand` skill, and to replace seen ones the `/rework` skill; do not write a batch freehand. Never bypass or loosen its gates
  (planned keys, evidence quotes, blind-solve records, overlap limits): skip the slot.
- A key never depends on a feature that was Preview in June 2026 (AC7 in `docs/question-standard.md`). Check the
  doc page for a Preview banner before keying a newer feature.
- Google Cloud products get renamed. Verify against current documentation rather than memory, and mark volatile
  facts *verify* in the theory.
- If you add a fact to a question that the theory does not teach, add it to the theory page too.
- **The question bank is private.** Never commit a question, never quote one into a tracked file (an issue, a PR, a
  doc, a test, a commit message), and never add `banks/` to an image. Tests run on the generated fixture bank
  (`tests/fixture_bank.py`); `ACE_TEST_BANK_DIR=banks/private pytest -q` runs them on the real one.
- `data/history.json`, `reports/`, `private/` and `scripts/retro_content.py` hold someone's personal attempts. They
  are gitignored. Never commit them or quote them into a tracked file. `.dockerignore` denies everything by default, so
  add to its allow list only what the image needs.
